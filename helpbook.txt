================================================================
HDC HELPBOOK
Simple guide: updating code, updating secrets, settings,
and everyday operations. Read the GOLDEN RULES first.
================================================================

WHERE EVERYTHING LIVES (on PythonAnywhere)
------------------------------------------------
Your code (server copy)     ~/HDC-MAIN
App settings                ~/HDC-MAIN/.env
                            (the app reads this itself; NEVER commit it)
Deploy secret (the "key")   ~/HDC-MAIN/deploy_secret.txt
                            (ONE line; must match the GitHub webhook
                            secret; NEVER commit it)
Deploy log                  ~/HDC-MAIN/deploy.log
                            (also visible at https://<you>.pythonanywhere.com/deploy)
Database                    path in .env -> HDC_DB_PATH
Web entry file (WSGI)       /var/www/<you>_pythonanywhere_com_wsgi.py
                            (written for you by the installer below;
                            it routes /deploy to the hook and everything
                            else to the app)
Installer (one command)     ~/HDC-MAIN/ops/pythonanywhere/install_deploy_hook.py
                            (creates the secret, writes the WSGI file,
                            prints the GitHub webhook values; --check
                            diagnoses, --restore undoes)

HOW DEPLOYING WORKS (the whole system, in one paragraph)
------------------------------------------------
You push to main on GitHub -> GitHub calls
https://<you>.pythonanywhere.com/deploy -> that runs deploy_hook.py
(one small file in this repo) -> it checks the secret, runs
"git pull", and reloads the site. That is everything. There is no
deploy server to start and nothing else to keep running.

GOLDEN RULES
------------------------------------------------
1. Do NOT edit code by hand on the PythonAnywhere checkout.
   You push from your own computer; the webhook pulls for you.
2. Never commit databases, zips, .env, deploy_secret.txt or
   deploy.log. They are gitignored for a reason.
3. After ANY edit to .env you must reload the web app:
       touch /var/www/<you>_pythonanywhere_com_wsgi.py
   (or click Reload in the Web tab). Settings do not apply until reload.
4. Secrets live ONLY in .env and deploy_secret.txt.
   Never paste them into chat, GitHub issues, or email.
5. After every push, open https://<you>.pythonanywhere.com/deploy
   in your browser. It shows what the hook detected and the last few
   deploys - you should see a new "OK deployed ..." line within
   about 30 seconds. (/deploy/health does the same thing.)


1. GETTING NEW CODE (the normal way)
------------------------------------------------
You edit code on your own computer. There:

    cd HDC-MAIN
    git status                       # see what changed
    git add .                        # stage changes (check what you add!)
    git commit -m "what you did"
    git pull --ff-only               # bring in others' changes, safely
    git push origin main

What --ff-only means: if your copy and GitHub can be joined cleanly,
it updates. If they cannot (a real conflict), it STOPS instead of
making a mess. Then solve the conflict, commit, push.

If git status shows uncommitted work you do not want to commit yet:
    git stash                        # park it away
    git pull --ff-only
    git stash pop                    # bring it back

After you push to main, GitHub's webhook automatically deploys to
PythonAnywhere. Wait about 30 seconds, then open in your browser:

    https://<you>.pythonanywhere.com/deploy

You should see a new line like:
    2026-09-13 14:02:11  OK deployed a1b2c3d: Fast-forward

"Starting a fresh copy on a new computer"? Just clone the repository
there, commit, and push as above. You do NOT copy .env,
deploy_secret.txt or the database between computers - the server
keeps its own.


2. FIRST SETUP ON PYTHONANYWHERE (once only - then never again)
------------------------------------------------
Open a PythonAnywhere Bash console and run:

    git clone https://github.com/rehmaahmed11/HDC-MAIN.git ~/HDC-MAIN
    cd ~/HDC-MAIN
    python3 -m venv ~/.virtualenvs/hdc
    ~/.virtualenvs/hdc/bin/pip install -r requirements.txt

Then create the app settings file (.env) in ~/HDC-MAIN:

    nano ~/HDC-MAIN/.env

It needs at least these lines (replace the passwords):

    HDC_ENV=prod
    HDC_SECRET_KEY=<long-random-string>
    HDC_DB_PATH=/home/<you>/HDC-MAIN/hdc_instance/hdc_erp.db
    HDC_INSTANCE_DIR=/home/<you>/HDC-MAIN/hdc_instance
    HDC_BOOTSTRAP_ADMIN_USERNAME=admin
    HDC_BOOTSTRAP_ADMIN_PASSWORD=<strong-password-for-first-login>

Make new random strings any time with:
    python3 -c "import secrets; print(secrets.token_hex(32))"

    chmod 600 ~/HDC-MAIN/.env

Now ONE command does the rest of the server side. It creates the
deploy secret (the "key"), writes the WSGI file for you, and prints
the exact values to paste into GitHub:

    cd ~/HDC-MAIN
    python3 ops/pythonanywhere/install_deploy_hook.py

You do NOT edit deploy_hook.py, and you do NOT paste anything into the
WSGI file - paths are detected (your username comes from the WSGI
file's own name, the repo from where the code lives). The installer
backs up the old WSGI file first and carries over any os.environ
lines it had, so a working site keeps working.

Then in the Web tab: set Source code to /home/<you>/HDC-MAIN,
Virtualenv to /home/<you>/.virtualenvs/hdc, and click the green
Reload button once.

Open https://<you>.pythonanywhere.com/deploy in your browser. It
prints what the hook detected (repo, wsgi file, secret, branch) plus
the last few deploys. If any line says MISSING, the installer tells
you which command fixes it. To re-check at any time without changing
anything:

    python3 ops/pythonanywhere/install_deploy_hook.py --check

Finally, on GitHub: repository -> Settings -> Webhooks -> Add webhook,
using the values the installer printed:

    Payload URL:  https://<you>.pythonanywhere.com/deploy
    Content type: application/json
    Secret:       the line the installer printed (= deploy_secret.txt)
    Events:       Just the push event

Done. Every future push to main now pulls + reloads automatically.
If you ever need the old WSGI file back:

    python3 ops/pythonanywhere/install_deploy_hook.py --restore


3. SYNCING THE SERVER BY HAND (only if the webhook is broken)
------------------------------------------------
Open a PythonAnywhere Bash console:

    cd ~/HDC-MAIN
    git pull origin main
    touch /var/www/<you>_pythonanywhere_com_wsgi.py

If requirements.txt changed in what you pulled, also update packages:

    ~/.virtualenvs/hdc/bin/pip install -r ~/HDC-MAIN/requirements.txt

Do NOT use "git reset" or "git clean" in ~/HDC-MAIN. If git pull
complains about your own edits on the server, do not force it -
those edits were never pushed to GitHub and forcing would delete
them. Commit and push them from your own computer instead.


4. ROLLING BACK TO AN OLDER VERSION
------------------------------------------------
Find the old commit id:

    cd ~/HDC-MAIN
    git log --oneline | head -20

Roll back (Bash console, server):

    cd ~/HDC-MAIN
    git checkout <old-commit-id>
    touch /var/www/<you>_pythonanywhere_com_wsgi.py

The site now runs that old version. To move forward again later:

    cd ~/HDC-MAIN
    git checkout main
    git pull origin main
    touch /var/www/<you>_pythonanywhere_com_wsgi.py


5. UPDATING SECRETS
------------------------------------------------
The app settings live in ~/HDC-MAIN/.env - open with:

    nano ~/HDC-MAIN/.env

Which secret does what:

    HDC_SECRET_KEY                  app/session key.
                                    Changing it logs ALL users out.
    HDC_BOOTSTRAP_ADMIN_PASSWORD    only used while the database has
                                    no users yet (fresh install).
                                    To change a login that already
                                    exists, see section 8 - use
                                    scripts/reset_admin_password.py.
    deploy_secret.txt               the GitHub hook "key" (separate
                                    file, one line). MUST match the
                                    value on GitHub.

Changing the webhook secret. Do it in this order, as fast as you
can (in between, GitHub pushes are rejected):

    1. Generate a new random value:
       python3 -c "import secrets; print(secrets.token_hex(32))"
    2. Paste it into ~/HDC-MAIN/deploy_secret.txt (one line), save.
    3. On GitHub: repository -> Settings -> Webhooks -> click the
       hook -> Secret field -> paste THE SAME value -> Update hook.
    4. Push any small commit (or redeliver in Recent Deliveries) and
       check https://<you>.pythonanywhere.com/deploy shows OK.

Same idea for the other secrets (edit .env, then reload the site
with touch, then check the site). After changing HDC_SECRET_KEY
expect everyone to be logged out once.


6. UPDATING OTHER SETTINGS
------------------------------------------------
All app settings are in ~/HDC-MAIN/.env, one per line:

    KEY=value

    HDC_ENV                 prod on the server
    HDC_SECRET_KEY          app/session key
    HDC_DB_PATH             the live database file
                            (do NOT change it if your data is there)
    HDC_INSTANCE_DIR        the data folder
    HDC_BOOTSTRAP_ADMIN_USERNAME / HDC_BOOTSTRAP_ADMIN_PASSWORD
                            only used for a brand-new empty database

Steps for any setting change:

    1. nano ~/HDC-MAIN/.env
    2. change the line, save
    3. touch /var/www/<you>_pythonanywhere_com_wsgi.py   (reload)
    4. open the site and check it still works


7. DAILY OPERATIONS (copy-paste commands)
------------------------------------------------
Did the last push deploy? (open in your browser):
    https://<you>.pythonanywhere.com/deploy

Read the same log on the server:
    tail -20 ~/HDC-MAIN/deploy.log

Watch the deploy log while you push:
    tail -f ~/HDC-MAIN/deploy.log

Reload the site by hand:
    touch /var/www/<you>_pythonanywhere_com_wsgi.py

BACK UP THE DATABASE (before risky changes - last resort restore):
    1. Web tab -> stop the web app (or just reload later)
    2. cp <HDC_DB_PATH> ~/hdc_erp-backup-$(date +%Y%m%d).db
    3. to restore: copy it back, then reload the web app


8. IF SOMETHING GOES WRONG
------------------------------------------------
Pushes are not deploying:
    1. open https://<you>.pythonanywhere.com/deploy in your browser
       (a new line should appear within ~30 seconds of the push)
    2. on GitHub: Settings -> Webhooks -> your webhook ->
       "Recent Deliveries" -> click the red one to see the exact
       error GitHub got back.

Pushes get "bad signature" in deploy.log:
    the secret on GitHub does not match deploy_secret.txt.
    Follow section 5 exactly (both sides must be identical).

Deploy log says FAILED (e.g. a merge conflict):
    someone edited code on the server. Do NOT force anything.
    Open a Bash console, look at "git status", and move those
    edits into a real commit from your own computer instead.

Site is broken after a deploy:
    roll back (section 4), fix the code on your own computer,
    push again.

Locked out of an existing admin login:
    HDC_BOOTSTRAP_ADMIN_PASSWORD is only read while the user table is
    EMPTY, so changing it in .env does nothing to a login that
    already exists. Reset the password from a Bash console instead:

      cd ~/HDC-MAIN
      set -a; . ./.env; set +a
      python3 scripts/reset_admin_password.py --show
      python3 scripts/reset_admin_password.py --username admin --prompt

    --show prints which database file it is about to touch. It refuses
    weak passwords, never echoes what you type, and --role admin also
    promotes the account. Reload the site afterwards, then log in.

After any fix, verify the two URLs:
    https://<you>.pythonanywhere.com/hdc/login
    https://<you>.pythonanywhere.com/deploy


9. NEVER DO THIS
------------------------------------------------
- edit code by hand inside ~/HDC-MAIN on the server
- git reset / git clean inside ~/HDC-MAIN on the server
- commit *.db, *.zip, .env, deploy_secret.txt, deploy.log
- paste secrets into chat, issues, or email
- delete ~/HDC-MAIN/.git, the database file, or the instance folder
- change the Web-tab Python version without matching the virtualenv
- edit the database file by hand while the site is running
