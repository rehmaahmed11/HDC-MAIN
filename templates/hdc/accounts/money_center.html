Split Transfer Logic (Smooth Handling)

When from_account != executed_by_account, the system auto-creates 2 rows with same group_id:

  • Step 1: transfer from Source → Executor (internal)
  • Step 2: actual type (e.g. payroll) from Executor → Final Destination

Overdraft checked on both steps sequentially. Void by group_id voids both. Duplicate guard treats group as one.

Example: Pay worker from Bank via Cash — Bank → Cash (step1 transfer), Cash → Worker (step2 payroll), same group_id.

{# How it works / diagram #}
How Money Flows — One Ledger, No Duplicates
Smooth Handling Guarantees
  • Single Source of Truth: Every module posts to hdc_account_txn unified ledger. Balances derived as opening + in − out, never stored.
  • Overdraft Protection: Company/cash/bank accounts cannot go negative. Checked in minor units (paisa) exact. Transfer checks both legs.
  • Duplicate Guard: source_type:source_id unique + _has_recent_duplicate time-window check prevents double entry.
  • Void Sync: Voiding source row (LabourLedger, Expense, etc.) auto-voids linked AccountTransaction and vice versa via _accounts_set_void_by_source.
  • Receipt Consistency: Every transaction generates receipt via _receipt_company_profile, linked by group_id for split transactions.
  • Reconciliation: Forensic scan finds orphan_txns, void_mismatch, duplicate_active, group_inconsistent, orphan_sources.
  • Day Lock: CF Register entries immutable, void-only, day lock via CashDayLock prevents back-dated edits, carries counted closing forward.
  • Excess Split: Overpayment auto-split: payment_part=min(amount,pending), excess=amount−payment_part, tip+advance must equal excess.

Money flow example — Worker Wage: TimeEntry calculates wage → LabourLedger entry_type=work (earned, non-cash) → Payroll run creates payment capped at balance → LabourLedger payment + Expense wage → AccountTransaction payroll via _accounts_post_labour_ledger_row from company to worker person account → Overdraft check in minor units → Duplicate guard via source_type:source_id → Receipt via company profile. Void sync ensures all three void together.
